# Вступление

Данный проект — экспериментальная C++ система для автоматизированного создания и обработки 3D-моделей зданий на основе фотографий, чертежей и других источников пространственных данных.

Проект ориентирован на применение методов компьютерного зрения, фотограмметрии, геометрического моделирования и искусственного интеллекта для построения структурированной 3D-модели здания.

---

## О проекте

Основная идея VisionBIM — объединить обработку исходных данных и построение структурированной модели здания в единой системе.

В качестве исходных данных могут использоваться:

- фотографии объектов;
- фотограмметрические данные;
- облака точек;
- изображения планов помещений;
- чертежи в форматах PNG/JPEG/PDF;
- геометрические данные, полученные в результате обработки исходных материалов.

На основе этих данных система должна постепенно формировать структурированное представление здания:

```text
Исходные данные
      │
      ├── Фотографии
      ├── Чертежи
      ├── Облака точек
      └── Другие данные
              │
              ▼
      Обработка данных
              │
              ▼
      Геометрический анализ
              │
              ▼
      Определение элементов здания
              │
              ├── Стены
              ├── Двери
              ├── Окна
              ├── Помещения
              ├── Перекрытия
              └── Другие элементы
              │
              ▼
      Структурированная сцена
              │
              ▼
         3D-модель
              │
              ▼
   Экспорт / визуализация
```

---

# Основные цели

Проект разрабатывается с несколькими основными целями:

1. Создать собственное геометрическое ядро для работы с 2D- и 3D-данными.
2. Разработать структуру сцены для представления здания в виде набора объектов.
3. Реализовать автоматическое построение геометрии по исходным данным.
4. Использовать методы компьютерного зрения и машинного обучения для анализа изображений и облаков точек.
5. Получить возможность формирования структурированной модели здания.
6. Подготовить основу для дальнейшей интеграции с Blender, Unreal Engine и другими 3D-инструментами.

# Геометрическое ядро

Модуль `Geometry` отвечает за математические и геометрические операции.

Например, `Vector2` используется для работы с координатами на плане здания:

```cpp
Geometry::Vector2 start(0.0, 0.0);
Geometry::Vector2 end(5.0, 0.0);
```

На основе геометрических примитивов создаются более сложные объекты.

Например:

```text
Vector2
   │
   ▼
Segment2D
   │
   ▼
Polygon
   │
   ▼
Room
```

3D-часть использует:

```text
Vector3
   │
   ├── Matrix4
   │
   ├── Transform
   │
   ├── Plane
   │
   └── BoundingBox3D
```

Это позволяет постепенно перейти от простой геометрии к полноценной пространственной модели.

# Модель сцены

Модуль `Scene` представляет здание как набор взаимосвязанных объектов.

Базовым классом является:

```cpp
SceneObject
```

Он предоставляет общие свойства объектов сцены:

- идентификатор;
- имя;
- трансформацию;
- видимость;
- состояние выбора;
- состояние активности.

От него наследуются специализированные объекты:

```text
SceneObject
│
├── Wall
├── Door
├── Window
├── Room
├── Floor
└── Building
```

---

# Владение объектами

Основной принцип архитектуры сцены:

> `Scene` является владельцем объектов сцены.

Это позволяет избежать проблем с дублированием объектов и управлением временем их жизни.

Например, если две соседние комнаты используют одну и ту же стену, в сцене существует только один объект `Wall`.

```text
             ┌───────────────┐
             │     Room A    │
             └───────┬───────┘
                     │
                     │ reference
                     ▼
                ┌─────────┐
                │  Wall   │
                └─────────┘
                     ▲
                     │ reference
             ┌───────┴───────┐
             │     Room B    │
             └───────────────┘
```

Комнаты хранят ссылки на стены, но не владеют ими.

Это позволяет корректно представлять общие элементы здания.

- фильтрация выбросов;

- сегментация объектов;

- выравнивание геометрии.

```text

     │
```

# Принципы разработки

Проект развивается по принципу постепенного усложнения.

Основные принципы:

### 1. Сначала фундамент

Сначала реализуются базовые геометрические структуры, затем объекты сцены и только после этого — алгоритмы реконструкции.

### 2. Модульность

Каждая крупная подсистема должна иметь собственную область ответственности.

Например:

```text
Geometry
    ↓
Scene
    ↓
Reconstruction
    ↓
AI / ComputerVision
    ↓
Application
```

### 3. Минимальная связанность

Компоненты не должны без необходимости владеть друг другом.

В частности, объекты сцены используют ссылки на связанные объекты, а централизованное управление объектами выполняется сценой.

### 4. Возможность дальнейшего расширения

Архитектура должна позволять добавлять новые типы объектов:

- колонны;
- балки;
- лестницы;
- крыши;
- перекрытия;
- мебель;
- проёмы;
- инженерные элементы.

## Быстрый старт — установка, настройка и запуск

Ниже приведены общие инструкции для разработки и локального запуска компонентов проекта. Репозиторий содержит C++ исходники и предполагает сборку через CMake. Приведённые команды рассчитаны на Windows (MSVC) и UNIX-подобные системы (Linux, macOS). Адаптируйте их под вашу среду.

### Зависимости (рекомендуемые)

- CMake 3.20+
- Компилятор C++17/C++20: MSVC (Visual Studio 2019/2022), GCC 9+, Clang 10+
- Git
- Для работы с изображениями/облаками точек в будущем: OpenCV, PCL (по мере интеграции)

### Сборка (общее)

1. Создайте директорию сборки и выполните CMake-конфигурацию:

```bash
mkdir build
cd build
cmake ..
```

2. Сборка проекта:

Windows (MSVC):

```powershell
cmake --build . --config Release
```

Linux / macOS:

```bash
cmake --build . -- -j$(nproc)
```

Примечание: текущий `CMakeLists.txt` в корне может быть пустым или служить заглушкой. Если CMake не находит целей сборки, откройте `CMakeLists.txt` и добавьте необходимые таргеты или используйте локальные CMake-файлы внутри подпроектов.

### Конфигурация

- Конфигурационные параметры (пути к данным, настройки логирования и т.п.) пока не стандартизированы в одном конфиг-файле. Рекомендуется создать собственный конфигурационный файл в формате JSON/YAML и передавать путь к нему в ваш исполняемый файл по аргументу командной строки (например, `--config config.json`).
- Для экспериментов с изображениями создайте папку `assets/images/` и поместите туда входные файлы.

### Запуск

После успешной сборки запустите исполняемый файл (пример имени `visionbim` — замените на фактическое имя вашего таргета):

```bash
./visionbim --help
```

Примеры режимов запуска (пока что демонстрационные):

```bash
./visionbim --mode analyze-plan --input ../assets/images/plan1.png --output ../output/scene.json

./visionbim --mode import-pointcloud --input ../assets/points/scan.ply --output ../output/mesh.obj
```

Если исполняемых целей нет, используйте или создайте небольшой тестовый раннер в `src/App/` для быстрой проверки компонентов геометрии и сцены.

### Запуск тестов и форматирование

- Если вы добавите тесты, используйте Catch2 / GoogleTest и добавьте цели `test` в CMake. Затем запускайте `ctest` из каталога `build`.
- Для форматирования кода рекомендуется использовать `clang-format` с конфигурацией `.clang-format` в корне проекта.

### Разработка на Windows (Visual Studio)

1. Откройте `build` в Visual Studio (`Open -> CMake or Open Folder`) или запустите генерацию решения:

```powershell
cmake -S . -B build -G "Visual Studio 17 2022"

cmake --build build --config Debug
```

2. Запустите и отлаживайте проект из Visual Studio.
